## 1. 实验目的

E1 在 E0 的基础上只做一件事：**给单尺度特征补上多分辨率结构**。它同样只读取 `neck`（256×64×64），但通过自建的 P2–P5 金字塔 + FPN 式 top-down 融合，让 decoder 自己生成多尺度表示。

它回答的问题：在不引入任何 ViT 中间层特征的前提下，仅靠 decoder 的金字塔化能带来多少提升？

## 2. 模型结构

```
neck [B, 256, 64, 64]
  ├─ stem: Conv1x1(256 → 128)                                    # P4 基准
  ├─ P5 = Conv3x3(stride=2)(P4)          → 32×32
  ├─ P3 = UpBlock(转置卷积 k=2,s=2 + GN + GELU)(P4)  → 128×128
  ├─ P2 = UpBlock(P3)                                 → 256×256
  └─ FPN top-down: P4' = Smooth(P4 + nearest_up(P5'))
                   P3' = Smooth(P3 + nearest_up(P4'))
                   P2' = Smooth(P2 + nearest_up(P3'))            # Smooth = Conv3x3 + GN + GELU
  └─ TwoStageSegHead(upsample_factor=4):
       3x3 Conv(128→64) + GN + GELU → ×4 双线性 → 3x3 Conv(64→32) + GN + GELU → 1x1 Conv(32→1)
       → logits [B, 1, 1024, 1024]
```

特点：

- 金字塔由 decoder **自己造**（转置卷积下采样/上采样），而非来自 encoder 的不同深度；
- 只有 top-down 路径（无 lateral 从 encoder 来的多级跳连），因为输入只有单层 `neck`；
- 无注意力、无 PPM/ASPP、无空洞卷积。

checkpoint 保存 37 个张量，文件 12.8 MB。

## 5. 曲线解读

### 5.1 epoch 1 就已经"全阳性"

第一轮验证的 FP-slice rate 就是 **0.9891**（6123 个阴性切片中 6056 个被判阳性），precision 只有 0.0687。也就是说，E1 的初始化输出偏置使其一上来就把几乎所有切片标成阳性，这与 E0 的"初始全阴"完全相反。

这种"全阳性"起点让它立刻拿到 pos-Dice 0.3688（因为阳性切片全被覆盖），但 `all-Dice` 只有 0.0375。

### 5.2 峰值（epoch 6–10）是"召回优先"的解

峰值附近 recall 0.52–0.70、precision 0.09，即模型覆盖了大部分病灶但面积远超真实病灶。FP-slice rate 高达 0.97–0.99，几乎是"无差别标记"。

由于主指标 pos-Dice 只统计阳性切片，**该指标对假阳性完全没有惩罚**（假阳性只体现在 precision 与 all-Dice 上），因此"大面积预测"在 pos-Dice 上得分最高——这是当前评估口径的一个结构性偏差。

### 5.3 epoch 10 之后：precision 上升、pos-Dice 下降

训练继续进行时，模型在做一件合理的事：**抑制假阳性**。

| 指标 | ep8（峰值） | ep40 | 变化 |
| --- | ---: | ---: | --- |
| precision | 0.0898 | 0.2718 | +0.182 |
| FP-slice rate | 0.9915 | 0.7844 | −0.207 |
| all-Dice | 0.0410 | 0.2242 | +0.183 |
| pos-Dice | 0.4461 | 0.3324 | **−0.114** |
| val_loss | 0.9789 | 0.9805 | +0.0016 |

也就是说，后续 32 个 epoch 让模型整体分割质量（precision、all-Dice）明显改善，但代价是把一部分真阳性也压掉了，从而在主指标上退化。

验证损失在 epoch 10 附近触及最低点（0.9763）后缓慢回升，训练损失却从 0.79 降到 0.58（降幅 27%），**训练/验证背离明确**，是典型的过拟合。1.06 M 可训练参数在 27090 张训练切片上仍然过拟合，说明问题不在参数量本身，而在于：
- 有效样本多样性低（每个 epoch 只采 3688 个样本，且增强很弱：翻转 + ±15° 旋转 + 0.9–1.1 缩放）；
- 病灶区域极小（阳性切片中位病灶 655 px，占整图 0.062%），模型更容易记住"大面积响应"的捷径。

## 6. 异常与事件

- 全程 15 次"梯度非有限，跳过该步"告警（13 次分布在 epoch 4–33），最多的一轮出现在 epoch 13（2 次）。
- 训练被用户手动启动（非脚本序列），日志无 console.log 副本。

## 7. 结论

1. **金字塔化本身带来了显著提升**：同样只读 `neck` 特征，E1 峰值 0.4461 vs E0 峰值 0.3355（+0.11），说明空间多分辨率的 decoder 结构非常关键。
2. E1 的最佳点出现在 epoch 8，此后 32 个 epoch 在主指标上持续退化，**当前配置下的 40 epoch 训练长度严重过量**。
3. E1 的 25.5% 峰值后衰退幅度是四组实验中最大的，说明这个 decoder 对过拟合最敏感（参数量最小但含大量高分辨率卷积）。
4. 与 E3 的对比（E3 读取四级特征，1.21 M 参数，峰值 0.4824）表明：**金字塔内的特征来源比金字塔本身更重要**。

## 8. 改进建议（针对 E1）

1. 若仍以 pos-Dice 为主指标，应在 epoch 8–12 早停；若要改善实际分割质量，应换用能惩罚假阳性的目标（如 Tversky / Focal-Tversky）并加入后处理。
2. 降低峰值后衰退幅度：缩短训练、提高 weight decay、加入更强的增强（垂直翻转、强度扰动、随机缩放裁剪）。
3. P2 层级（256×256×128）是主要算力开销，可考虑去掉 P2 或用轻量深度可分离卷积，验证损失是否可接受。
